# OmniLens 5.0.3 — Universal Data Intelligence Platform

**🌐 Live Demo:** [https://omni-lens-sepia.vercel.app/](https://omni-lens-sepia.vercel.app/)

> **"Your data. Clear answers. Better decisions."**  
> Plain-language data understanding tool designed to help anyone turn raw spreadsheets and records into evidence-backed findings and actionable decisions without technical skills.

---

The default experience is deliberately small: one upload box, four synthetic examples grouped into Government, Business and Personal use, a short result, a few charts, a small number of findings, next steps, Ask a question, Fix these for me, Share and Compare. Technical details remain behind an optional disclosure.

## Product behaviour

### First screen

The first screen contains one upload area, then four sample datasets organised into three use-case groups: Government & public services (District Tax Report and fictional Crime Statistics), Business (Shop Sales), and Personal (Personal Money Ledger). The examples are generated by `backend/sample_data.py`, and the downloadable CSVs in `samples/` are generated from that same source so the buttons and files stay aligned. There are no goal-selection steps before upload.

### After upload

OmniLens identifies the likely table shape and chooses a matching analysis approach. A result includes:

- A plain-language headline about the data, not a large data-quality score.
- Up to three useful charts. A chart is omitted when there is no defensible calculation for it.
- Up to five findings. Each has what happened, supporting evidence and a next step.
- An ordered checklist of practical actions.
- A "See these rows" view for the source records behind a finding, plus an Excel evidence download.
- Three suggested questions and a plain-English question box.
- A "What this file can't tell us" note.
- Separate full-width sections for Share, Fix these for me, and Compare two files. They are not grouped together in a single toolbar.
- Share options for PDF, Word, WhatsApp-ready text and print.
- A cleaning preview with before/after rows, an approval list and a change log. The uploaded DataFrame is not modified.
- A two-file comparison that automatically selects shared measures and matching group fields where possible.
- Optional technical details for people who want them.

## Eight data shapes

The detector looks for eight common data shapes and chooses a playbook:

1. **Records** – one row is likely one transaction, person or event. Looks for trends, group totals, repeated rows, blank fields and unusual values worth reviewing.
2. **Grouped summary** – rows describe category groups and can contain Count, Sum and Average fields. It excludes All/Total rows from rankings, does not add averages or percentages, and computes weighted averages as total Sum divided by total Count when matching fields exist.
3. **Time series** – dates plus measurements. Shows movement over time, gaps and high/low periods where the data supports them.
4. **Wide table** – period or subject values stored in multiple columns. Compares those columns without changing the uploaded file.
5. **Survey** – response distributions and rating summaries. Categorical answers are shown as response shares, not added as numbers.
6. **Register/list** – focuses on blank details, repeated entries and named Indian-format checks.
7. **Text-heavy** – shows frequent words and links back to original lines. Word frequency is not sentiment or proof of a theme.
8. **Place-based** – compares wards, districts, areas or regions. A numeric ward code is treated as a place label, not a quantity.

If the shape is uncertain, OmniLens asks what one row represents. It does not silently turn an unclear file into a confident conclusion. If no playbook fits, it gives a limited overview and says what it could not infer.

## Supported inputs

- CSV with common delimiters and encoding variations.
- Excel `.xlsx` and `.xls`; the most table-like sheet/header is selected and the import note names other sheets where present.
- JSON arrays, objects and nested lists of records.
- TXT and HTML tables/text. Recognisable Google Pay activity text can be split into transaction records.
- Text-based PDFs with selectable tables. The largest detected table is extracted and its page is reported.

**Not included in this version:** OCR for scanned/image-only PDFs, general image upload, private Google Sheets OAuth, email import, or audio/video transcription. Scanned PDFs are rejected with an explanation rather than silently treated as empty data. For a complex workbook, verify the selected sheet and preview before relying on its result.

The default upload limit is 25 MB. Configure it with `OMNILENS_MAX_UPLOAD_MB`.

## Privacy and deployment boundaries

- No accounts, database, cloud object store or persistent upload directory are used by this application.
- Uploaded files are sent from the browser to the OmniLens server you choose, parsed in memory, and retained in an in-memory session with a default 30-minute expiry. Sessions are periodically cleared and also disappear when the process/container restarts.
- The app does **not** mean that a file never leaves the user's device: it is transmitted to the server running OmniLens. For offline use, run the app on a local computer or an approved internal server and do not expose it to the public internet.
- PAN, GSTIN, Aadhaar-style number, phone, PIN, IFSC and email checks are format checks only. They do not verify a person's identity, official registration, checksum, account ownership or whether the value is real.
- Common personal fields are masked in previews, evidence downloads and cleaned-file exports. This is best-effort masking, not guaranteed anonymisation. Inspect exports before sharing them.
- One Uvicorn worker is used intentionally because session data is held in that process's memory. Multiple workers or replicas do not share sessions. For multi-worker deployments, add a carefully designed shared ephemeral session service before enabling them.
- This is a self-hostable prototype, **not a formally security-audited or certified government system**. It has no user authentication, role-based access control, departmental audit identity or formal compliance certification. Before departmental use, put it behind approved authentication and TLS, restrict network access, review retention and incident procedures, and complete the organisation's security/privacy review.

## Run locally on Windows

Requirements: Python 3.11+ (Python 3.13 is suitable), Node.js 20+ and npm.

### 1. Backend

From the project folder in PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

Check the backend at <http://127.0.0.1:8000/health> and the API documentation at <http://127.0.0.1:8000/docs>.

### 2. Frontend

Open a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the Vite URL printed in that terminal (usually <http://localhost:5173>). The Vite development server forwards `/api` requests to the local FastAPI server.

Convenience scripts are also included:

```powershell
.\scripts\start-backend.ps1
.\scripts\start-frontend.ps1
```

Open separate terminals for the two scripts.

## Run with Docker

From the project folder:

```bash
docker compose up --build
```

Open <http://localhost:8000>. To stop it:

```bash
docker compose down
```

The container has no data volume configured. Uploaded sessions exist only in the container process memory and are lost when it stops. For offline deployment, build the image on a connected build machine and transfer it using your organisation's approved image transfer process.

## API routes

| Route | Purpose |
|---|---|
| `GET /health` | Health and version check |
| `POST /api/analyze` | Parse and analyse an uploaded file |
| `POST /api/sample/{shop\|tax\|expenses\|crime}` | Run one of the four synthetic examples |
| `GET /api/sample-file/{shop\|tax\|expenses\|crime\|shop_earlier\|shop_later}` | Download a synthetic sample CSV or one side of the shop comparison pair |
| `POST /api/confirm-rows` | Re-run analysis after a user clarifies the row meaning |
| `POST /api/ask` | Answer a question with a calculation, chart and evidence rows |
| `GET /api/evidence/{session_id}/{finding_id}` | Masked source rows for a finding |
| `GET /api/evidence/{session_id}/{finding_id}/excel` | Download those rows as Excel |
| `GET /api/share-text/{session_id}` | WhatsApp-ready text summary |
| `GET /api/report/{session_id}?format=pdf` | PDF report with charts, findings and caveat |
| `GET /api/report/{session_id}?format=docx` | Word report |
| `GET /api/clean/preview/{session_id}` | Suggest possible cleaning changes |
| `POST /api/clean/preview-approved` | Preview selected changes only |
| `POST /api/clean/apply` | Download an approved cleaned copy with change log |
| `POST /api/compare` | Compare two uploaded files using automatically matched columns |
| `GET /api/technical/{session_id}` | Optional technical detail for the current session |

## Current limitations to keep visible

- Hindi and Marathi switches translate the main interface controls and common labels. Field names, original category values and some generated analysis sentences may remain in English in this build; this is partial localisation, not a full translation of every possible data-specific sentence. Read-aloud uses the voices available in the user's browser/device.
- Date interpretation can be ambiguous when dates use numeric day/month formats and neither component disambiguates the order. The import report states the assumption; check the preview.
- Very small, unusual, heavily merged or multi-table documents may not have enough structure for a reliable automatic interpretation. Confirm the row meaning or upload a clean table export.
- A format warning is not proof that a value is invalid. A statistical unusual-value flag is not proof of an error, fraud or misconduct.
- A result describes only the data supplied. It cannot establish missing source records, representativeness, or the cause of a pattern.

## Product test that still requires people

The automated tests check calculations and file handling. They do not replace the requested five-person usability test. Before a hackathon or public-sector demonstration, give the app to five people unfamiliar with data tools, say nothing, and observe whether each can upload a file, understand the headline and share the result without asking what to click. Record where they hesitate and simplify those exact moments.
